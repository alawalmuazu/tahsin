System Architecture · v7.1.0

Tahsin Academy

CodeIgniter 3 school-management platform for Tahsin Academy (live at tahsinacademy.ng). Motto: Excellence In Deen & Duniya. Single-school build (APP_VERSION 7.1.0); branch_id still exists in the schema but always resolves to SCHOOL_ID.

1. What the app is

Tahsin Academy is a single-school ERP built on CodeIgniter 3. The public brand is Tahsin Academy; older Smart School strings are rewritten in MY_Controller::brandName(). Stack: PHP, MySQL/MariaDB, Apache with .htaccess rewriting. App version is 7.1.0 (application/config/constants.php).

is_multi_school() returns false. Rows remain keyed by branch_id for historical schema reasons, but that key only ever takes one value: SCHOOL_ID (see get_loggedin_branch_id()). Do not read a branch from the request.

On top of the classic school modules (students, fees, exams, HR), the app adds an Academy layer for halaqah tahfiz, performance drills, genome overview, and parent broadcast drafts — see section 8.

2. How a request moves through the code

Browser
  → index.php (front controller)
  → application/config/routes.php
  → MY_Controller (install check, global settings, timezone, branch currency)
  → Admin_Controller / User_Controller / Frontend_Controller / Authentication_Controller
  → module controller (Student, Fees, Exam, …)
  → model + MySQL
  → views/layout/index.php (header + sidebar + $sub_page)

index.php is the only public PHP entry. Environment comes from CI_ENV or a .env file; production is not hardcoded.

Autoload (application/config/autoload.php) always loads:

  • libraries: database, session, form_validation, upload, app_lib
  • helpers: url, form, security, general
  • model: application_model

Almost every staff screen extends Admin_Controller, which redirects to /authentication if the session is missing.

5. Branch & school identity

This build is single-school. Identity constants live in application/config/constants.php:

  • SCHOOL_ID — the only allowed branch_id value
  • SCHOOL_NAME — Tahsin Academy
  • SCHOOL_MOTTO — Excellence In Deen & Duniya

Resolve the school through get_loggedin_branch_id() / $this->application_model->get_branch_id(). Controllers still pass branch_id into queries so the schema stays compatible with the Smart School lineage.

Board / multi-school pickers are disabled. Education-board tables may still exist in the dump, but they are not an active product surface in this build.

Parent portal

Guardian Details on Student → Add and Parents → Add/Edit write the same parent row. Role 6 is that guardian’s portal login. Extra phone numbers are stored on parent.extra_phones from both forms.

A new parent row in Parents_model::save() also inserts login_credential role 6 with active = 0. The username is the parent email. Login stays off until a superadmin, admin, or director opens the parents list and approves it (parents/approve → Parents_model::approvePortal()). Approval sets active = 1 and must_change_password = 1. An unapproved login is told to wait for a director or an admin.

The first successful sign-in is sent to profile/password and cannot open the rest of the portal. After the new password is saved, the session is destroyed and the parent returns to authentication/index/changed. That password change sets login_credential.pwa_required = 1 (column from application/migrations/parent_portal_approval.sql). The next sign-in is held on profile/install_app until the browser is standalone or the app install event fires, which calls profile/pwa_done and clears the flag. Admin_Controller and User_Controller both enforce this gate.

8. Academy reporting layer

Sidebar group Academy (main_menu = academy). Data layer: Academy_model. Migrations: application/migrations/academy_engine.sql, academy_engine_v2.sql, recitation_categories.sql, clean_akhlaq_telemetry_tags.sql, academy_session_review.sql, academy_session_by_category.sql.

Session review: Admin, director, or superadmin assigns students on academy_review/assign. Tick many students and save once; the save replaces only that teacher’s list. Filters: name or register number, Student Category (pwd_category), Section, Class, and Programme Category (student_category). A student may sit on several teachers at once. The assignment unique key is branch + academic session + teacher + student (uq_ats_teacher_student). Each teacher records only their own list. A session is unique per teacher, day, recitation category, and tahfiz milestone (uq_acs_milestone). Saving the same portion again the same day is refused with the earlier date and time. A different ayah or category opens a new director review. When every assigned student has an entry from that teacher for that category’s day, the session moves recording → pending_director and the director (and superadmin) get a bell notice. Director approve moves it to pending_admin and notifies the teacher; reject notifies the teacher and the next complete save can resubmit. Admin acknowledge publishes that teacher’s scores on the parent and student dashboards and sends today’s WhatsApp digest for that teacher’s assigned students; reject notifies the director and the teacher. Other teachers’ work stays hidden until their own sessions are acknowledged. Muraja'a and Tarteel analysis stay inside the school. Parents receive the sealed clip after director approve and admin acknowledge — they do not see analysis bands or Tajweed reports.

Session lifecycle

Each teacher has their own day. A student can sit on several teachers (Quran, Maths, English, and so on). Saving an assignment replaces only that teacher's list. One teacher's acknowledgement publishes only that teacher's scores for that date. Within Quran, each recitation category and each saved milestone is its own review row.

  1. Assign. On academy_review/assign, pick one teacher, filter by name or register number, Student Category, Section, Class, or Programme Category, tick many students, and save once. The same student can remain on other teachers. Unique key: uq_ats_teacher_student (branch, academic session, teacher, student).
  2. Record. The teacher saves only students on their own list. A student counts for today when this teacher wrote the drill (evaluator_id) or the tahfiz row (instructor_id). Status stays recording until the list is complete. The same facilitator cannot save the same category, surah, and ayah range twice in one day; the save returns the earlier completed_at and the session status.
  3. Auto-submit. When the last assigned student is recorded for that category milestone, the day moves to pending_director. The director (role 9), superadmin (role 1), and the teacher get a bell notice (academy_notice).
  4. Director. Session Review loads the weak clip for pending_director, pending_admin, and acknowledged rows so both director and admin can play, read the transcript, and read Tajweed mistakes before they decide. Approve moves the day to pending_admin and notifies the teacher, admin (role 2), and superadmin. Reject sets director_rejected and notifies the teacher. The next time that teacher's list is complete, it resubmits.
  5. Admin. Acknowledge on one row, or Release today's sealed sessions, sets the day to acknowledged. That teacher's portion and audio appear on the parent and student dashboards. The same step sends the tahsin_sealed_digest WhatsApp template for that teacher's assigned students when the session date is today. Every phone on the guardian is messaged: primary parent.mobileno plus each number in parent.extra_phones (duplicates removed after E.164 normalize). A guardian with no phone falls back once to the student’s mobile; if that is empty too, the student is skipped. Director, superadmin, and the teacher are notified. Reject on a single row still sets admin_rejected and does not send WhatsApp. Academy → Broadcast → Send digests remains for a later resend.

Tarteel engine

Config: application/config/tarteel.php (not documented with secrets). Modes: auto (cloud then local), cloud, local. Live highlight: cloud WSS, with optional local stream on ws://127.0.0.1:8001/v1/recite/stream (school PC). Full-clip FastConformer final runs on the Hostinger VPS (:8002; :8001 is another app there); the browser posts to same-origin academy_students/tarteel_final, which proxies to local_final_upstream (avoids HTTPS mixed content). Local XAMPP still proxies to 127.0.0.1:8001. Deploy: python scripts/deploy_tarteel_vps.py. Weights stay off GitHub and off Cloud PHP. Quran reference SQLite from the Tarteel APK is phone-mushaf only; this site and the engine use Uthmani ayah JSON / api.alquran.cloud.

Quran text for the mushaf comes from api.alquran.cloud (uthmani). Uploaded proof clips land under uploads/academy_tahfiz/. The saved report stores engine label, transcript, correct words, Tajweed mistakes, and word timings (not the audio blob). Old clips without timings still open the mushaf popup; the highlight then walks the words evenly across the clip length.

Tarteel analysis levels

Verdicts on academy_review/tarteel use each student’s assigned band from Tarteel settings. Defaults: Beginner strength from 60% / at most 3 mistakes, improve below 40% or at 6 mistakes; Medium 75% / 1 and 60% / 4; Advanced 90% / 0 and 75% / 2. Unassigned students use Medium. Category rollups follow the per-session verdicts, not a fixed global percentage.

WhatsApp Cloud API (Broadcast)

Admin acknowledgement sends the parent digest itself through Meta Graph API (application/libraries/Whatsapp_cloud.php, Academy_model::dispatchSealedDigests → deliverCloudDigests). Configure under School Settings → WhatsApp (table whatsapp_cloud_config); file config is fallback only. The template body is student, teacher, portion, and the seal line. Optional native audio or video follows when the file is a public HTTPS link. Academy_broadcast still has a manual send for a resend, plus click-to-chat. Sends are stored in academy_broadcast_log (one log row per phone). Migrations: whatsapp_broadcast_log.sql, whatsapp_cloud_config.sql, parent_extra_phones.sql.

Guardian and parent are the same parent row (role 6). Student → Add Guardian Details and Parents → Add/Profile share the same + extra-phone fields (application/views/parents/_extra_phones.php). Academy_model::parentPhoneList() builds the send list from primary + extras.

Recitation categories & portion modes

Required before save (see Academy_model::recitationCategories()): Hifz Fauq, Hifz Taht, Talqeen, Murajaa Qareebah, Murajaa Baeedah, Musaffa, Qiyaamullail. Portion modes: Full Surah, Single Ayah, From–To Ayah, Summu'i, Rubbu'i, Safha.

Telemetry columns on academy_tahfiz_record (v2): accuracy_score, mistake_word_count, mistake_breakdown (MEDIUMTEXT JSON report), audio_url, video_url, tarteel_status, recitation_seconds, plus recitation_category. Session columns: recitation_category, milestone_id.

9. How views are assembled

Staff pages almost never load a full HTML file themselves. They set:

  • $this->data['title']
  • $this->data['sub_page'] — e.g. 'student/view'
  • $this->data['main_menu'] — sidebar highlight

Then they call $this->load->view('layout/index', $this->data).

layout/index.php wraps header, topbar, sidebar, and the inner page. Public marketing pages go through Home and branch-specific CMS settings.
