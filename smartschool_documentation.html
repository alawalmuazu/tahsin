Tahsin Academy Codebase Analysis

A technical reference for the Tahsin Academy school-management platform. Motto: Excellence In Deen & Duniya.

1. High-Level Overview

SmartSchool is a PHP-based multi-tenant school management system built on the CodeIgniter 3 framework. It is designed to operate at a state government scale, connecting a centralized Education Board to thousands of individual schools (branches) in a single deployment.

6. Database Schema Highlights

The database contains over 100 tables structuring the massive operational data required for state-wide deployment. A critical aspect of this schema is how user entities (Parents, Students, Staff) are linked.

Parent & Student Relational Model

The system uses a strict One-to-Many relationship between Parents and Students. The student table contains a parent_id foreign key. This allows a single Parent/Guardian account to be linked to multiple children across the system. The login_credential table sits above all user entities, securely handling authentication.

7. Key Design Patterns

  • Branch Scoping: Almost all queries are scoped by branch_id using Application_model::get_branch_id().
  • Session-Based Data: Academic year separation via session_id.
  • Dynamic Translations: The translate() helper auto-inserts missing strings into the DB.
  • Addon System: Extensible plugin architecture (e.g., SaaS, 2FA modules).

Security Considerations

When exporting entities, the Password hashes are strictly excluded from the CSV outputs to maintain system integrity. The Username is included to allow cross-referencing.

10. Identity & Access Management (Login & Registration)

SmartSchool centralizes login for all entity types (Students, Teachers, Employees, Parents) through a unified authentication gateway while segregating registration methodologies based on administrative roles.

Unified Login Architecture

All users authenticate at /authentication. The system queries the centralized login_credential table, which maps the user to their respective underlying entity table via the user_id and role fields.

Registration / Onboarding Flows (Hybrid IAM)

SmartSchool employs a Hybrid User-Led Credentialing Architecture. Rather than Administrators generating and distributing plain text passwords, the system empowers end-users to securely set their own credentials via two distinct pathways, both of which culminate in a centralized Administrative Approval phase.

Flow Scenario Trigger Point Credential Generation Account State
Scenario A: Admin Invitation Admin creates the user record (Employee, Student, Parent) but selects "Send Setup Invitation Link". A secure setup_token is generated. The user clicks the link to choose their own Username and Password. Starts at active = 2 (Pending Setup). Moves to active = 0 after setup.
Scenario B: Public Registration User navigates to the public /registration portal (can be disabled globally by Admin). User inputs their desired details, Username, and Password on the public form. Starts at active = 0 (Pending Admin Approval).
Admin Approval (Final) Admin reviews pending accounts in the /credential_approvals dashboard. Admin approves the account, granting system access. Moves to active = 1 (Fully Active).

Dynamic Role Assignment & Security

When an Admin creates an Employee, they assign a specific System Role (e.g., Teacher, Accountant, Receptionist). Students and Parents are permanently hardcoded to Role 7 and Role 6, respectively. All passwords are automatically hashed using pass_hashed() before ever touching the database.
